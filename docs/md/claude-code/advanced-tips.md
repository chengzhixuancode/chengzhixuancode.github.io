## 范式转换：从打字员到项目经理

### 认清 Claude Code 的本质

**传统 AI 编程工具的本质：** 你写半行代码，它帮你续写后半行。它的角色是"辅助者"，你是"主导者"。

**Claude Code 的本质：** 它是一个能理解整个项目的"系统级协作者"。你描述目标，它规划路径并执行。它的角色是"执行者"，你是"架构师+审查者"。

### 用法对比

| ❌ 错误用法 | ✅ 正确用法 |
|-----------|-----------|
| 写一行、问一句 | 描述完整任务，让 AI 自主执行 |
| 盯着终端看 AI 打字 | 启动任务后去做别的事 |
| 让 AI 帮你写函数 | 让 AI 帮你完成整个功能模块 |

**核心转变：** 你的工作不再是写代码，而是定义目标 → 分配任务 → 验收结果。当你习惯了这种模式，效率才会有质的飞跃。

### 200K+ 上下文窗口的核心优势

Claude Code 的核心竞争力之一是其超过 200K token 的上下文窗口。这意味着：

- **无需手动提供上下文：** 你不需要把相关文件一个个贴给 AI
- **全局理解：** AI 能理解你整个项目的架构
- **跨文件修改：** AI 能一次修改多个相关文件

## 五大核心机制

Claude Code 的能力不是堆砌出来的，而是围绕五个核心机制构建的。理解这五个机制，才算真正入门。

### Skills —— 预封装工作流模板

**是什么：** 把常用操作流程封装成可复用的"技能包"。比如"写单元测试"、"做代码审查"、"创建新 API"。

**为什么重要：** 消除重复沟通成本。你不需要每次都告诉 AI "先看代码风格，再按规范写，别忘了加注释"，一个 Skill 就全包了。

**使用方式：**

技能存放在 `~/.claude/skills/` 目录中，可以通过斜线命令调用，而且可以链式组合：

```bash
# 在一条提示词里链式调用多个技能
Run /refactor-clean, /add-tests, /test-coverage

# 技能还可以管理代码导航图，节省上下文
~/.claude/skills/codemap-updater.md
```

**常见内置技能：**

- `/init` - 初始化项目说明书
- `/review-pr` - 代码审查
- `/security-review` - 安全审查
- `/commit` - 生成提交信息
- 自定义技能可以满足团队特定需求

### Hooks —— 事件驱动自动化

**是什么：** 当某个事件发生时，自动执行一段脚本。与技能不同，它不需要你手动调用。

**钩子类型一览：**

| 类型 | 触发时机 | 常见用途 |
|------|---------|---------|
| PreToolUse | 工具执行前 | 验证、安全检查，阻止危险命令 |
| PostToolUse | 工具执行后 | 格式化输出、生成反馈循环 |
| Stop | 完成回复后 | 发送桌面通知（如 tmux 提醒） |

**推荐用法：** 使用 hookify 插件——与其手写 JSON 配置，不如让 AI 帮你对话式地生成钩子。

**示例配置：**

```json
{
  "hooks": {
    "preCommand": [
      "npm run lint -- --fix {{filename}}"
    ],
    "postCommand": [
      "echo 'Command completed at $(date)'"
    ]
  }
}
```

### MCP —— 连接外部服务，但需节制

**是什么：** MCP（Model Context Protocol）让 Claude Code 直接连接外部服务——数据库、GitHub、Supabase 等——无需复制粘贴，直接在对话中操作数据。

⚠️ **关键警告：** MCP 会大量消耗上下文。你的上下文窗口在压缩前可能只有 20 万 token，但如果同时激活太多 MCP，实际可用空间可能只剩 7 万。性能会显著下降。

**实践经验：**

- 配置 20–30 个 MCP，但每次项目只激活 5–6 个
- 通过项目级 `.claude.json` 的 `disabledMcpServers` 字段来管理
- **经验法则：** 安装 20–30 个，激活不超过 10 个，工具总数控制在 80 个以内

### Subagents —— 并行分身术

**是什么：** 面对复杂任务时，Claude Code 可以拆分出多个独立的 Subagent 并行工作。它们在后台或前台运行，拥有受限的工具权限，不会占用主代理的上下文窗口。

**最佳实践：** 工具少 → 执行专注。一个只负责代码审查的子代理，不应该同时拥有数据库访问权限。

**常见子代理分类：**

```
~/.claude/agents/
├── planner.md         # 拆解功能任务
├── architect.md       # 系统设计决策
├── code-reviewer.md   # 质量与安全审查
├── build-error-resolver.md  # 专注错误分析
├── refactor-cleaner.md      # 死代码清理
└── doc-updater.md     # 保持文档同步
```

**使用场景：**

- 探索代码库 → 用 Explore 子代理
- 制定实现计划 → 用 Plan 子代理
- 实现功能 → 用 implement 子代理
- 代码审查 → 用 check 子代理
- 并行处理多个独立任务，效率倍增

### CLAUDE.md —— 动态进化的项目记忆

CLAUDE.md 是 Claude Code 理解项目的核心。高阶用法是让它**动态进化**：

- 整个团队共用一个 CLAUDE.md，提交到 Git
- 每周都有人往里加东西
- 规则超简单：每次看到 Claude 做错了，就把"别这样做"写进去

**复利工程：** 每一次纠错都变成团队资产。每次遇到 AI 犯错，就把规则写进 CLAUDE.md。经过几个月的积累，Claude 会越来越贴合你的团队。

## 特殊输入前缀

Claude Code 支持三个特殊的输入前缀，让你的操作更快捷：

| 前缀 | 作用 | 示例 |
|------|------|------|
| `#` | 添加到记忆（CLAUDE.md） | `# 本项目使用TypeScript` |
| `@` | 文件路径自动补全 | `@src/app.js` |
| `!` | 直接执行 bash 命令 | `! npm test` |

**使用技巧：**
- 用 `#` 快速把项目规则添加到 CLAUDE.md
- 用 `@` 快速引用项目中的文件，不用手动敲路径
- 用 `!` 快速执行命令，不用等 Claude 生成工具调用

## 高级工作流模式

### Plan 模式的正确打开方式

Anthropic 内部专家建议：**90% 的时间应该使用 Plan 模式**。

**Plan 模式的工作流程：**

1. 用户提出需求
2. AI 先输出详细的执行计划
3. 用户确认/调整
4. AI 再动手执行

**为什么重要：** 没有 Plan 模式时，AI 容易"一上来就猛干"，写到一半发现方向不对。Plan 模式让你在执行前就能发现问题，成本更低、质量更高。

### 验证闭环：让 AI 检查自己的作业

这是最重要的一条实践经验。

**普通流程：**
需求 → AI 生成代码 → 人工 review → 提交

**闭环流程：**
需求 → AI 生成代码 → AI 自检 → AI 修正 → 人工 review → 提交

实际数据：代码质量提升 2-3 倍（以 bug 数量衡量），返工率从 20%+ 降至 5% 以下。

### 并行作战：多实例协同的效率倍增器

单个 Claude Code 实例已经很强，但真正的效率爆发来自并行。

**实操方法：**

- 终端开多个实例：每个标签页跑一个独立任务
- 网页版再跑几个：文档类工作可以在浏览器处理
- 利用 Subagent：在单任务内部并行处理
- Git Worktrees 技巧（避免代码冲突）：

```bash
# 创建工作树
git worktree add ../project-feature-a feature-a
git worktree add ../project-feature-b feature-b

# 每个工作树跑一个 Claude 实例
cd ../project-feature-a && claude
```

### 思维深度控制：Extended Thinking 扩展思考

Claude Code 支持 **Extended Thinking（扩展思考）** 功能，可以根据问题复杂度控制推理深度。这不是斜杠命令，而是通过关键词触发的特殊语法：

让 Claude 在回答前进行深度思考，展示**完整解题过程**而不只是答案。类比：就像数学考试，有人直接写答案，有人写完整解题过程。Extended Thinking 就是让 Claude 展示完整解题过程。

| 关键词 | Token 预算 | 响应时间 | 适用场景 |
|--------|-----------|---------|---------|
| `think` | ~1,500 | 5-10秒 | 一般问题、代码分析 |
| `think hard` | ~3,000 | 10-20秒 | 复杂问题 |
| `think harder` | ~8,000 | 20-30秒 | 架构决策 |
| `ultrathink` | ~16,000 | 30-60秒 | 关键决策 |

**启用方式：**

1. **Tab 键切换**（最简单）：在交互模式中按 Tab 键，可以切换 Extended Thinking 开/关
2. **关键词触发**（灵活控制）：在提问开头加上对应前缀：

**使用示例：**

```
# 代码性能分析
think: 分析这个函数的时间复杂度，找出可能的性能瓶颈

# 技术选型对比
think hard: 比较 Redis 和 Memcached 在这个场景下的优劣，给我推荐方案

# 系统架构设计
think harder: 设计一个支持百万级 QPS 的短链接服务架构

# 关键决策分析
ultrathink: 帮我分析三种不同架构方案，对比各自的优缺点，给出最终推荐
```

**省钱技巧：** Extended Thinking 会消耗更多 Token！只在真正需要时使用：

| 问题类型 | 推荐方式 | 原因 |
|----------|---------|------|
| 语法查询 | 普通模式 | 简单问题不需要深度思考 |
| 代码分析 | `think` | 需要基础分析 |
| 架构设计 | `think hard` | 需要权衡多方方案 |
| 技术选型 | `ultrathink` | 关键决策值得深思 |

### TDD 工作流：测试驱动开发

这是 Claude Code 最擅长的工作流之一：

1. 用自然语言描述功能需求
2. Claude 先生成测试用例（Plan 模式）
3. 确认测试用例后，生成实现代码
4. 自动运行测试，不通过则自动修正
5. 所有测试通过后，提交代码

### 5 阶段 Agent 编排

黑客松冠军团队提出的 5 阶段编排模式：

| 阶段 | 角色 | 产出 |
|------|------|------|
| Phase 1: RESEARCH | Explore Agent | research-summary.md |
| Phase 2: PLAN | Planner Agent | plan.md |
| Phase 3: IMPLEMENT | TDD Guide Agent | 代码改动 |
| Phase 4: REVIEW | Code Reviewer Agent | review-comments.md |
| Phase 5: VERIFY | Build Error Resolver | 问题修复 |

**关键规则：**

- 每个 Agent 只有一个清晰的输入，产出一个清晰的输出
- 输出变成下一阶段的输入
- 永远不要跳过阶段
- 阶段之间用 `/clear` 清理上下文
- 中间输出存到文件里

### Prompt 工程实战精选

**技巧 1：先给角色，再给任务**

❌ 差的写法：
```
帮我解释这段代码
```

✅ 好的写法：
```
你是一名有 10 年经验的 Python 后端工程师，擅长性能优化。
请解释以下代码的逻辑，并指出可以优化的地方。
```

**技巧 2：让 Claude 先问问题再写代码**

```
我要写一个文件处理系统。在开始写代码前，请先问我 5 个关键问题，
确认你完全理解需求后再开始。
```

## 核心原则

经过 10+ 个月的深度使用，归纳出五条最核心的原则：

### 01. 把配置当微调，不是架构

文件组织要简单清晰，不要过度工程化。配置是服务于工作流的，而不是目的本身。

### 02. 上下文窗口是稀缺资源

关闭不用的 MCP 和插件，是最直接的性能优化。激活的工具越少，Claude 的执行质量越高。

### 03. 并行执行才是正确姿势

用 `/fork` 分叉对话，用 git worktree 运行多实例。顺序等待是对算力的浪费。

### 04. 把重复工作自动化

格式化、lint、提醒这类事，应该交给 Hooks，不要每次手动触发。

### 05. 给子代理限定工具范围

工具越少，执行越专注，结果越可控。不要让子代理拥有它不需要的权限。

## 结语：从工具使用者到工作流设计者

回顾整个学习路径，你会发现一个清晰的进阶脉络：

- **心法阶段：** 从"工具使用者"变成"任务管理者"
- **入门阶段：** 掌握基本命令，跑通第一个任务
- **机制阶段：** 理解五大核心机制
- **技巧阶段：** 熟练运用各种命令和快捷键
- **工作流阶段：** 将技巧组合成系统化流程
- **体系阶段：** 建立个人化的提效资产

这个脉络的终点，是从"会用工具的人"变成"会设计工作流的人"。

最后，记住这七句话：

1. 从 `/init` 开始，让 AI 先学习项目
2. 多用 Plan 模式，想清楚再动手
3. 建立验证闭环，让 AI 检查自己
4. 并行是效率的杠杆，别让 AI 闲着
5. CLAUDE.md 是复利工程，每次纠错都是资产
6. 用 Sonnet 起步，复杂任务切 Opus
7. 把重复的做成命令，把常用的做成 Skills

Claude Code 代表的不仅是工具的进步，而是人机协作模式的根本转变。从"人写代码、AI 补全"到"人定方向、AI 执行"，开发者的角色正在从"编码者"向"架构师+审查者"演进。
